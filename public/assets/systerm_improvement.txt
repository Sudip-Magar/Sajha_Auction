I am building a Laravel auction system. I want to implement an estimated-value/depreciation feature for auction products.

IMPORTANT:

* First inspect the existing codebase thoroughly.
* Understand the existing auction/product models, migrations, Livewire components, enums, validation, database structure, and UI before making changes.
* Do NOT unnecessarily create duplicate tables, fields, models, or logic.
* Follow the existing project's coding conventions and architecture.
* Reuse existing fields and components where appropriate.
* Do not break existing auction functionality.

FEATURE REQUIREMENTS

The purpose of this feature is to provide sellers and bidders with an estimated value of an auction item based on its original purchase price, age, and condition.

Example:

Original purchase price = Rs. 200,000
Purchase date = 1 year ago
Condition = Excellent

Base estimated value:
Rs. 200,000 × (1 - 20% depreciation)
= Rs. 160,000

Then apply the condition adjustment.

Suggested condition adjustments:

Excellent = +5%
Good = 0%
Fair = -10%
Poor = -20%

For Excellent:

Rs. 160,000 × 1.05
= Rs. 168,000 estimated value

The system should then suggest a starting auction price around 75–85% of the estimated value.

For example:

Estimated value = Rs. 168,000
Suggested starting price = approximately Rs. 126,000–143,000

However, the system must NOT force the auction to stay below the original purchase price.

If bidding exceeds the original purchase price, the auction should continue normally.

For example:

Original price = Rs. 200,000
Current bid = Rs. 210,000

This is allowed.

The system may display a warning/reference message such as:
"Current bid exceeds the original purchase price."

Do NOT automatically reject bids above the original purchase price.

DEPRECIATION RULES

Use the following initial laptop depreciation rules unless the existing application already has a better configurable depreciation mechanism:

0–6 months     = 10%
6–12 months    = 15–20%
1–2 years      = 25–35%
2–3 years      = 40–50%
3–4 years      = 55–65%
4–5 years      = 65–75%
5+ years       = 75%+

For the initial implementation, use a deterministic value rather than a range.

Recommended values:

0–6 months     = 10%
6–12 months    = 18%
1–2 years      = 30%
2–3 years      = 45%
3–4 years      = 60%
4–5 years      = 70%
5+ years       = 75%

Formula:

base_estimated_value =
original_price × (1 - depreciation_rate)

Then:

condition_adjusted_value =
base_estimated_value × condition_factor

Condition factors:

Excellent = 1.05
Good      = 1.00
Fair      = 0.90
Poor      = 0.80

STARTING PRICE

Calculate a suggested starting price from the estimated value.

Use approximately 80% as the default:

suggested_starting_price =
estimated_value × 0.80

The seller should still be able to manually change the starting price if the existing auction design allows seller-defined prices.

Do not force the calculated value as the actual auction starting price unless the existing business rules require it.

RESERVE PRICE

If the existing auction system supports a reserve price, integrate the estimated value with it.

Do NOT automatically make the estimated value the reserve price.

If reserve price functionality does not exist, do not introduce it unless necessary. Instead, document where it could be added later.

IMPORTANT DISTINCTION

Keep these concepts separate:

1. original_price

   * The price the seller originally paid.

2. estimated_value

   * System-calculated reference value based on age/depreciation/condition.

3. suggested_starting_price

   * System suggestion for where bidding can begin.

4. starting_price

   * Actual price used by the auction.

5. reserve_price

   * Minimum amount accepted by seller, if supported by the existing system.

6. current_bid

   * Current highest bidder's amount.

7. final_price

   * Winning auction price after auction completion.

Do not overwrite original_price with estimated_value.

Where appropriate in the seller auction creation/edit form, show:

Original Purchase Price
Purchase Date
Product Condition
Estimated Value

Actual Starting Price

Example:

Purchase Date: 2025-08-15
Condition: Excellent

Estimated Value: Rs. 168,000
Suggested Starting Price: Rs. 134,400

The estimated value and suggested starting price should preferably be calculated automatically when the required fields are available.

If the project uses Livewire/Alpine.js, follow the existing architecture instead of introducing unnecessary JavaScript.

BIDDER UI

On the auction detail page, show the estimated value as a reference if this fits the existing UI.

For example:

Estimated Value: Rs. 168,000
Current Bid: Rs. 175,000

If current bid exceeds the original purchase price, display a non-blocking warning:

"Current bid is above the original purchase price."

Do NOT say that the bidder is definitely losing money because the system cannot know the bidder's personal valuation.

IMPORTANT BUSINESS RULE

Original purchase price is NOT the maximum auction price.

Example:

Original price = Rs. 200,000
Estimated value = Rs. 160,000
Current bid = Rs. 210,000

Rs. 210,000 is valid.

The system should not prevent the bid merely because it exceeds the original purchase price.
